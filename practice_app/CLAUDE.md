# CLAUDE.md — practice_app

给 Claude Code（及其它 AI 工具）在 `practice_app/` 目录下干活时看的工程规范。项目功能性文档见
[`README.md`](./README.md)（怎么用、目录结构、API）和 [`HANDOFF.md`](./HANDOFF.md)（按时间顺序的开发交接记录、
已知坑）。这份文件只放"以后所有改动都要遵守的硬规则"，不放某一次改动的细节说明。

## Windows 计划任务 / 看门狗规范（2026-09-06 起）

任何注册成 Windows 计划任务、以巡检/看门狗方式常驻运行的脚本（不限于 [`keep-alive.ps1`](./keep-alive.ps1)，
以后新增的同类脚本都算），**必须做到对用户完全无打扰**——用户在用这台电脑做别的事的时候，看门狗每隔几分钟
跑一次不应该有任何能感知到的动静：不跳出窗口、不自己打开浏览器、不弹系统通知/气泡提示、不抢焦点。

**具体要求**：

1. **两个"隐藏"开关都要设，缺一个都不够**——这是两套独立的机制，只设其中一个在部分 Windows 版本上仍可能
   闪一下窗口：
   - 计划任务动作里，启动 `powershell.exe` 时带 `-WindowStyle Hidden`（管的是"这个进程自己的窗口"）；
   - 注册任务时 `New-ScheduledTaskSettingsSet` 要带 `-Hidden`（管的是"任务本身"，跟上面那个不是一回事）。
   参考写法见 [`README.md`](./README.md#开机自启--公网访问可选) 里的注册脚本片段。
2. **脚本内部再拉起的每一个子进程也要 `-WindowStyle Hidden`**——不管是 `node.exe`、`cloudflared.exe`
   还是别的什么，看门狗自己隐藏了，子进程没隐藏一样会露出来。
3. **不能触发任何形式的浏览器自动打开**。像 [`start-practice-app.ps1`](./start-practice-app.ps1) 这种本来是给人
   交互式双击用的脚本，交互式场景下打开浏览器是合理的，但看门狗调用它时必须传 `-NoBrowser`（或等价开关）
   —— 一个每 5 分钟跑一次、还自己弹浏览器标签页的"看门狗"，对用户来说跟"每 5 分钟被打断一次"没区别。
4. **不使用 `MessageBox`、`New-BurntToastNotification`、`msg.exe` 之类会弹提示/通知的机制**——看门狗的
   运行状态（干了什么、有没有出错）写日志文件即可（参考 `data/keep-alive.log` 的做法：一行一条时间戳+
   信息，供人想查的时候自己打开看，不是主动推给人看）。
5. **幂等，不是"重要"但同样必须遵守**：看门狗每次运行前要先判断"是不是已经健康"，健康就什么都不做直接
   退出——不能因为"反正要巡检"就无条件重启一遍正常运行的东西。已经在 `keep-alive.ps1` 里踩过一次坑：
   保存地址用的时间戳解析漏了一段，导致健康检查每次都误判失败、把正常运行的隧道重启一遍——表现上"看起来
   在正常巡检"，实际上每 5 分钟都在做一次没必要的重启，这类 bug 不会有窗口弹出来提示你，只能通过看日志或者
   留意"地址怎么一直在变"发现，写完看门狗后务必手动验证"健康时真的是空操作"这一条，不能想当然。

**为什么定这条规范**：2026-09-06 给 practice_app 加开机自启+掉线重连的看门狗（`keep-alive.ps1`，
每 5 分钟巡检一次、长期常驻）时，一开始只设了 `-WindowStyle Hidden` 漏了任务级别的 `-Hidden`，用户
主动提出"看门狗要保持不打扰的无头模式"才补上。之后同类脚本直接照这份规范做，不用重新踩一遍。
